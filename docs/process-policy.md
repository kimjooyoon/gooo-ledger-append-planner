# Process policy

The bootstrap commit contains CI and `.gooo` authority exactly once. Its scope is preserved as `BOOTSTRAP_SCOPE_VIOLATION` because the feature implementation was included in that commit; this fact is never rewritten as `CLOSED`. Post-bootstrap direct-to-main count is zero; implementation changes move through one open pull request at a time. The initial development session observed local validation attempts `3`, Go tests `9`, Go builds `0`, `go run` compilations `3`, Go vet `1`, and conformance `2`. This makes the development process `REFUTED`; those results are not product conformance evidence. GitHub Actions is the only verification authority for release evidence.

The release workflow creates a release once for an annotated tag and immediately reads back immutable REST metadata. It must never rewrite an existing tag/release. The release dossier must preserve the exact tag object, target commit, release, asset, workflow run, job, artifact, size, and SHA-256 identities.

The v0.31.0 ledger fixture is read-only evidence. Historical `local_validation_executions=1/process=REFUTED` and wrong insertion-point attempts remain motivation and counterexample context, not a performance claim.

The bootstrap CI observation is preserved in `process/bootstrap-evidence.json` with run `33453310225` and job `99687812628`. Corrective PR CI emits a separate GitHub Actions evidence artifact. The independent verifier is a separate consumer that does not import the planner executor; it re-reads `.gooo`, the immutable lock, transaction, output plan, receipt, and materialized copy.

The v2 transaction manifest is semantic authority for the exact immutable target binding: before source-tree digest, denominator, state counts, structural anchors, planned file set, and after invariants. A mismatched v0.32 source tree remains `SOURCE_TREE_DIGEST_MISMATCH`/`REFUTED`; an absent target binding remains `UNKNOWN`. GitHub Actions observes the four-case v0.31/v0.32 corpus, and only the matched v0.1→v0.2 pair supports the narrow immutable-binding metric `1→2`; broader improvement claims remain `UNKNOWN`.

The v3 transaction manifest adds `.gooo` semantic types: semantic sources are `SEMANTIC_APPEND_ONLY`, while derived projections are `DERIVED_PROJECTION`. A projection replacement is permitted only in a caller-owned temporary copy and only when the manifest binds its exact before digest, projection kind, source semantic digest, and after invariant. The executor does not maintain an arbitrary Go path allowlist. Missing or incomplete projection authority emits the complete six-field `UNKNOWN` frontier; before-digest mismatch, source-semantic mismatch, undeclared targets, and unexpected deletion are `REFUTED`. The preserved v0.31/v0.32 corpus remains non-regressed, and the v0.33 projection case is `CLOSED` with deterministic replay, exact rollback, and zero input-repository writes.

The local v0.33→v0.34 transaction adopts the immutable explanation-carrying compiler v0.3.0 release from `kimjooyoon/gooo-reflexive-compiler-slice`, whose release scope is `ONE_COMPILER_PHASE_ONLY`. An upstream v0.34.0 ledger tag/release was not observed; the transaction therefore binds upstream v0.33.0 as its immutable baseline and does not claim an unobserved upstream release.
